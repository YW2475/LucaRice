# Agent Note: LucaRice 业务数据使用 SQLite

Status: implemented

[English](2026-09-12-lucarice-business-data-sqlite.md) | 中文

## 问题

LucaRice 曾将账户记录、浏览器登录状态、田块档案和农事记录分散存放在 JSON 文件中。更新一条记录会重写整份文件，关联数据也无法原子查询和更新。

## 决定

LucaRice 将业务记录保存在 `.lucarice-data/lucarice.sqlite3`。账户插件负责账户、登录状态、会话归属和已归档会话；田块管理插件负责同一数据库中的田块档案和农事记录，田块天气插件读取这些田块档案行。两个连接都使用 SQLite WAL 模式和五秒忙等待。

首次使用时，账户插件会在数据库没有账户时导入 `accounts.json`。田块插件会为每位用户一次性导入现有的 `fields/*/field.json` 与 `events.json`。原 JSON 文件保持不变，作为恢复来源，后续不再承担写入。

Harness 会话日志、模型凭据文件、知识包和图片资产继续采用原有存储方式。这使 LucaRice 业务数据与 vendored Harness 保持隔离，也让模型密钥不进入普通业务数据库。

## 曾考虑的替代方案

- **继续使用 JSON 文件**：能保留现有格式，但日常账户和田块更新仍会重写完整文档。
- **把 Harness 会话日志和凭据移入该数据库**：这些记录的所有权和安全要求不同，与 LucaRice 耦合会增加 Harness 升级难度。
- **为田块单独使用数据库**：单一数据库便于部署和迁移，同时表的所有权仍由各自插件保持。

## 影响

LucaRice 业务数据可作为一个 SQLite 文件迁移，并支持关联行的原子更新。每个账户和田块用户在成功首次导入后都会留下标记，避免重复导入旧记录。服务运行期间备份时必须同时包含 SQLite 数据库及其 WAL 伴随文件。

## 验证

本地迁移检查导入旧账户和田块记录，并通过 SQLite 实现验证账户归属、已归档会话、田块读取、农事记录写入和田块档案更新。
